# 자동화 도구 비교 분석 보고서 (Make vs n8n)

## 1. 워크플로우 개요

**공통 워크플로우:** Codyssey 로그인 시도 → 로그인 성공/실패 판정(조건 분기) → 분기별 Gmail 알림 발송

- Trigger 1개: 스케줄(매일 9시)
- Action 2개 이상: HTTP 로그인 요청, Gmail 발송(성공/실패 각각)
- 조건 분기(Router/Filter) 1개: 로그인 성공 여부에 따른 분기, 두 경로 모두 1회 이상 실행 확인됨

## 2. 도구별 구현 과정 요약

### Make
- HTTP 모듈(내장 앱)로 `POST /authenticate` 요청을 보내 로그인 처리
- Router 모듈로 로그인 성공/실패 두 경로 분기
- 각 경로 끝에 Gmail "Send an email" 액션을 연결해 성공/실패 알림 발송
- 실행 결과: 두 분기(1st/2nd) 모두 초록 체크로 실행 완료 확인

### n8n
- 스케줄 트리거(Every Day 9AM) 노드로 시작
- HTTP Request 노드(Codyssey Login)로 로그인 요청
- 별도 노드(Check Login Result)로 응답 파싱 후 IF/Switch 노드(Login Success?)로 분기
- 분기별로 Gmail 노드(Notify Success / Notify Failure) 연결
- 실행 결과: 전체 노드 초록 체크로 실행 성공 확인

두 도구 모두 동일한 논리 구조(트리거 → 로그인 요청 → 결과 판정 → 분기 → 알림)를 구현했으나, n8n은 "결과 확인"을 별도 노드로 명시적으로 분리한 반면 Make는 Router 자체에서 필터 조건으로 분기를 처리한 점이 구조상 차이다.

## 3. 비교 항목

| 비교 항목 | Make | n8n |
|---|---|---|
| **UI/UX** | 원형 노드와 곡선 연결선의 시각적 캔버스, 데이터 흐름이 애니메이션으로 표시됨 | 사각 노드와 직선 연결선, 각 노드에 실행 성공 여부가 체크 아이콘으로 즉시 표시됨 |
| **설정 난이도** | 모듈 설정 UI가 앱별로 표준화되어 있어 초반 진입은 쉬우나, Router/Filter 조건식 문법은 별도 학습 필요 | 노드 설정이 JSON/표현식(`{{ }}`) 기반이라 초반 학습 곡선이 있으나, 이해하면 세밀한 데이터 가공이 가능 |
| **연동 서비스 범위** | 3,000개 이상의 사전 제작된 앱 커넥터 보유, 커넥터 품질과 문서화가 우수 | 400개 이상의 통합 노드 제공, 부족한 연동은 HTTP Request나 Code 노드로 직접 구현 가능해 유연성이 높음 |
| **무료 플랜 범위** | 무료 플랜: 월 1,000크레딧, 활성 시나리오 2개, 최소 실행 간격 15분 (2026년 기준) | 클라우드는 무료 플랜이 없고 14일 체험만 제공(Starter 기준 월 2,500회 실행부터 유료), 대신 셀프호스팅(Community Edition)은 완전 무료이며 실행 횟수 제한이 없음 |
| **실행 로그 확인 방식** | 시나리오 실행 이력(History)에서 모듈별 입출력 데이터를 클릭해 상세 확인 가능 | 각 노드 위에 성공/실패가 색상 아이콘으로 즉시 표시되고, 노드 클릭 시 입출력 JSON을 바로 확인 가능 |
| **과금 기준** | "크레딧(구 오퍼레이션)" 단위: 모듈 실행 1회 = 1크레딧 | "실행(execution)" 단위: 워크플로우 1회 실행 전체가 1회로 계산되어, 단계가 많은 워크플로우일수록 상대적으로 유리 |

## 4. 각 도구의 장단점

### Make
- **장점**
  - 시각적 라우터/필터 구조가 직관적이어서 분기 로직을 한눈에 파악하기 쉬움
  - 방대한 사전 연동 앱 덕분에 Gmail·Google Sheets 등 SaaS 연동이 매우 빠름
  - 무료 플랜만으로도 소규모 테스트/학습용 워크플로우는 바로 시작 가능
- **단점**
  - 무료 플랜의 크레딧(1,000/월)과 15분 최소 실행 간격이 실사용에는 금방 부족해짐
  - 복잡한 데이터 가공(반복 파싱, 커스텀 로직)은 별도 모듈(Text parser, Iterator 등)을 추가로 조합해야 해서 워크플로우가 길어짐

### n8n
- **장점**
  - Code 노드/표현식으로 원하는 로직을 자유롭게 작성할 수 있어 복잡한 조건·데이터 가공에 강함
  - 셀프호스팅 시 완전 무료 + 실행 횟수 무제한이라 과금 걱정 없이 운영 가능
  - 노드 단위 실행 결과가 즉시 시각적으로 표시돼 디버깅이 빠름
- **단점**
  - 클라우드 버전은 무료 플랜이 없어(14일 체험만 제공) 학습 초반부터 유료 결제 또는 셀프호스팅 인프라 구축이 필요
  - 셀프호스팅 선택 시 서버 관리(배포, 백업, 업데이트)라는 추가 부담 발생
  - 표현식 문법에 익숙해지기 전까지는 Make보다 진입장벽이 다소 높음

## 5. 어떤 상황에서 적합한지

- **Make**가 적합한 경우: 비개발자 중심 팀에서 SaaS 앱 간 연동 위주의 단순~중간 복잡도 워크플로우를 빠르게 구축하고 싶을 때. 시각적 분기 구조로 로직을 팀원과 쉽게 공유하고 싶을 때도 유리하다.
- **n8n**이 적합한 경우: 실행 횟수가 많거나 예산 제약이 커서 장기적으로 무료(셀프호스팅)로 운영하고 싶을 때, 혹은 표준 커넥터로 처리하기 어려운 커스텀 로직(코드 기반 가공, 복잡한 조건)이 필요한 경우.
- 본 과제처럼 소규모 스케줄 트리거 + 단순 분기 + 이메일 알림 정도의 워크플로우라면 두 도구 모두 무리 없이 구현 가능하며, 실제 선택은 "팀의 기술 숙련도"와 "장기 운영 비용" 두 축으로 결정하는 것이 합리적이다.

## 6. 과금 리스크 관련 참고

- Make 무료 플랜(1,000크레딧/월, 2 활성 시나리오)만으로 본 과제의 스케줄+분기+알림 워크플로우 테스트가 가능했음
- n8n은 클라우드 무료 플랜이 없어, 본 과제는 셀프호스팅 또는 로컬 실행 환경을 전제로 진행함(유료 결제 없이 완수 가능)
